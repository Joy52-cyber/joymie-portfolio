What This Is

How I test a game when I can't see its code. I used real games from Google Play on a normal Android tablet. Here is what I found, what I got wrong, and how I caught it.

1. An Error That Wasn't a Bug

Coin Master · 3 launches
  • The same error showed up in the log every time the game started, 3 out of 3.
  • Before reporting it, I checked if any other app on the tablet showed it. Google Play Movies did, with the exact same error.
  • So it was a tablet issue, not the game's bug. I didn't report it.

Lesson: happening every time doesn't make it a bug. One extra check saved a developer from chasing a problem that wasn't theirs.

2. A Real Bug

Block Blast · confirmed two ways
  • The log: the game tried to load its Firebase reporting code and failed, 12 times on every launch.
  • The app file: I opened the installed app and searched all 16 code files. That code was missing, while similar code (AppsFlyer, ThinkingData) was there.
  • Both pointed to the same thing, so I reported it. I wrote the likely cause as a guess, not a fact.

3. My Mistake

  • I searched the log for freezes and found 10, the worst at 3.8 seconds.
  • Only 6 were from the game. The rest came from Android itself and a pen app on the tablet.
  • I had searched by text instead of filtering to the game only. My own tool already did this right; I just didn't use it.
  • The real result: 6 freezes in 2 minutes, worst 3.8 seconds, mostly from the same action.

What changed: my report steps now filter to the game only, so nobody else makes the same mistake.

How I Write Reports

  • Say how sure I am about each item: confirmed, possible, or ruled out.
  • Give steps anyone can follow to see it themselves.
  • Say what the report does not prove.
  • Keep the ruled-out items in, so people can see what was checked.

Tool

I ran all of this with Verdict, a tool I built. It starts the game on a real device, records everything the game logs, and saves each run with proof.
